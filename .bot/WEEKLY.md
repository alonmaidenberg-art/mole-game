# הבדיקה השבועית

ההוראות לסשן השבועי שרץ לבד, בלי שאלון נמצא כדי לענות על שאלות.
אלון ביקש שהבוט **יתקן לבד** ויעלה, ושיוסיף **שלבים ומצבי משחק למשחקים הקיימים**.

## מה לעשות, לפי הסדר

1. **להביא את הקוד**
   ```
   git clone https://github.com/alonmaidenberg-art/mole-game
   cd mole-game
   ```

2. **להריץ את צייד הבאגים**
   ```
   node .bot/hunt.js
   ```
   זה משחק בכל 96 המשחקים במקביל ומחפש תקלות שנכונות לכל משחק: קריסה,
   מסך קפוא, מסך ריק, שליטה מתה, מספרים הרוסים, ויציאה מגבולות המפה.
   הדוח המלא נכתב ל-`.bot/last-run.json`.

3. **לתקן כל ממצא ברמה high או med.** לא לסמוך על הדוח לבד — לפתוח את
   המשחק, לשחזר את התקלה, להבין למה היא קורית, ורק אז לתקן. ממצא שלא
   מצליחים לשחזר הוא ממצא שקרי: לרשום אותו ביומן ולא לגעת בקוד.

4. **להריץ את הצייד שוב** ולוודא שהממצא נעלם ושלא נשבר שום דבר אחר.

5. **להריץ את המבקר: `node .bot/playtest.js`.**
   זה לא מחפש משחקים שבורים אלא משחקים שעובדים אבל לא נעשו נכון —
   כפתורים קטנים מכדי ללחוץ עליהם באצבע, טקסט קטן מכדי לקרוא, דברים
   שגולשים מחוץ למסך, משחק שרץ לאט, ומשחק שנגמר אחרי שתי שניות שוב
   ושוב. הדוח נכתב ל-`.bot/last-playtest.json`. זה רץ סדרתית ולוקח זמן.
   לתקן 3–5 ממצאים בכל שבוע, לא את כולם בבת אחת. אלה בדיוק הדברים
   שאלון ביקש: "דברים שעובדים, פשוט לא עשית אותם נכון".

6. **להוסיף תוכן למשחק אחד או שניים** — שלב חדש, מצב משחק, אתגר, דרגת
   קושי. לא משחק חדש. לבחור משחק שלא קיבל תשומת לב לאחרונה (אפשר לפי
   `git log -- <תיקייה>`).

7. **לעדכן את החנות.** `shop.js` מושך את `shop.json` בכל טעינה, אז
   מספיק להוסיף שם פריט והוא מופיע לכולם — אין צורך לגעת בקוד.
   להוסיף **פריט אחד או שניים בשבוע**, ולא יותר, כדי שהחנות תישאר
   מעניינת ולא תוצף.
   - פריט חייב אפקט שבאמת ממומש. `th` חייב להתאים ל-`data-th` שקיים
     ב-`theme.css`, ו-`fx` חייב להתאים למה ש-`shop.js` יודע לצייר
     (`trail`, `rtrail`, `ftrail`, `burst`, `confetti`), עם ה-`grp`
     הנכון (`trail` או `click`). פריט שקונים ולא קורה כלום הוא גזל.
   - אם רוצים אפקט או ערכה חדשים — קודם לממש אותם ב-`theme.css` או
     ב-`shop.js`, ורק אז למכור.
   - **לבדוק שזה באמת עובד:** לקנות את הפריט בדפדפן, להפעיל אותו,
     ולראות שהדף משתנה. לא להסתפק בכך שה-JSON תקין.
   - לא לגעת בפריטים קיימים ולא לשנות מחירים של פריטים שכבר נמכרו.

8. **לבנות מחדש את "מה בא לך לשחק?"** אם נוסף או השתנה משחק:
   ```
   python3 .bot/build-guide.py
   ```
   הקטע הזה נכתב כ-HTML אמיתי לתוך `index.html` (בין הסימונים
   `GUIDE:START` ו-`GUIDE:END`) כדי שמנוע חיפוש יראה אותו בלי להריץ
   קוד. **אל תערכו אותו ביד** — עורכים את הסקריפט ומריצים מחדש.
   הטקסט שם בנוי ממילות ז'אנר שאנשים מחפשים ("משחק ריצה אינסופי",
   "הגנת מגדלים", "משחק לשניים"). **אסור לכתוב שם שמות של משחקים של
   חברות אחרות** כדי להיתפס בחיפושים שלהם — גוגל מזהה את זה כספאם,
   וזה גם לא מה שאלון רוצה שהאתר שלו יהיה.
   אם נוסף משחק, לוודא שהוא גם ב-`sitemap.xml`.

9. **לעלות**
   ```
   git add -A && git commit && git push
   ```
   Cloudflare Pages בונה מגיטהאב לבד, אז דחיפה = האתר מתעדכן.

10. **לכתוב לאלון** סיכום קצר בעברית: מה נמצא, מה תוקן, מה נוסף.
   אם לא נמצא כלום — לומר את זה בשורה אחת ולא להמציא עבודה.

## גבולות שאסור לחצות

אלו בקשות מפורשות של אלון מהעבר. הן גוברות על כל ממצא של הבוט.

- **אל תיגע בקוד תנועת העכבר של טניס שולחן.** גם אם נראה שיש שם באג.
- **משחקי הצבעים שומרים על הצבעים המדויקים שלהם.**
- **אל תשנה את הרווחים והמרווחים בלובי.** אלון אמר: "אני אוהב שיש רווחים,
  זה טוב, אל תשנה את זה."
- **אל תעתיק קוד או תמונות ממשחקים של אחרים.** לא מפוקי, לא ממשחקים של
  חברים, לא מסרטונים ששלח. בונים מאפס.
- **אל תמחק משחקים** ואל תוריד משחק מ-`games.json`.
- **אל תשנה תאריכים אחורה** בשום קובץ או קומיט.
- **אל תתקין Node או PartyKit** אצל אלון.
- **תמיד לכתוב לו בעברית.**

## כללי עבודה

- תיקון אחד = קומיט אחד, עם הסבר מה היה שבור ולמה התיקון עובד.
- לא לשכתב משחק שלם בגלל באג אחד. התיקון הכי קטן שפותר את הבעיה.
- אם תיקון דורש החלטה על איך המשחק מרגיש (קושי, מהירות, איזון) — לא
  להחליט לבד. לתקן את הצד הטכני, ולשאול את אלון על השאר בסיכום.
- אם הצייד עצמו נשבר (לא המשחקים) — לתקן את `.bot/hunt.js` ולומר את זה.
